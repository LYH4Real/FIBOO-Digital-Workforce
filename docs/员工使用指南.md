# 员工使用指南

## 安装前

- Windows x64 和 WorkBuddy；市场初版在 WorkBuddy 5.5.6 的插件机制上验证。
- 当前公司发行仓库暂时公开，添加市场无需 GitHub 授权；若未来改为私有，则需要仓库读取权限及本机 Git 登录。不要把密码写进市场地址。
- 员工自己的钉钉登录、小红书浏览器登录，以及需要生图时自己的 Wave Key。

## 按需安装

双击市场包根目录的 `安装市场.cmd`，公司仓库地址已经预填。完成后，在 WorkBuddy 技能页的插件区域找到“FIBOO-数字员工市场”。

可以只安装“fiboo 产品资料”，它会带上钉钉办公；也可以只安装图片生成。需要完整的小红书流程时安装“小红书内容策划”，其依赖会自动安装。安装过程中如果 WorkBuddy 提示填写图片 Key，在它的敏感配置入口输入，不在聊天里粘贴。

## 首次配置

### 浏览器

告诉 WorkBuddy：“初始化 Kimi 浏览器助手”。从 https://www.kimi.com/products/kimi-webbridge 进入 Chrome 或 Edge 扩展商店，由员工点击添加。插件自带脚本下载并校验本地桥接程序；连接检查必须返回 `connected=true`。

在自己的浏览器登录小红书，随后使用笔记采集。插件不会分发其他员工的登录态。Kimi 原生状态检查会报告扩展/桥接版本不匹配；依官方指引对齐，正在工作时不擅自重启桥接服务。

### 钉钉

告诉 WorkBuddy：“初始化钉钉办公插件并引导我登录”。DWS 已随插件提供。依提示完成本人授权；访问 fiboo 产品库还需要相应钉钉资料权限。

FIBOO 辅助程序会把 DWS 复制到 `~/.fiboo/bin/dws.exe`。当前任务还找不到新命令时，直接使用这个绝对路径；重启 WorkBuddy 后用户 PATH 生效。插件升级不替换你的钉钉账号配置。

### 图片生成

在 Wave 插件的 WorkBuddy 配置入口填写获分配的 API Key。密钥由 WorkBuddy 保存为本地敏感配置，不进入公司市场包。生成图片默认保存在员工的 `~/Pictures/FIBOO/generated_images`，不会随插件缓存更新被清除。

### 业务脚本

两个业务 Skill 含 Python 脚本。可使用 WorkBuddy 自带 Python 3.10+，无需自行假定命令行已经存在 `python`。插件的 `scripts/run-python.ps1` 会自动发现运行环境。PDF 文本提取还需要 `pypdf`；技能按需在任务环境安装其声明的依赖。

## 日常使用

示例：“从公司资料库查询 fiboo 多重蛋白粉，读取我给的参考笔记，先做一份可确认的小红书内容策划。”

内容策划先交付方案，确认后再生成图片。插件不会自行发布笔记。资料更新来自实时查询；Skill 流程或程序更新来自市场新版。

## 检查更新

市场安装器会开启 WorkBuddy 的原生自动更新设置，同时为当前 Windows 用户设置每天 10:00 和登录时的只读检查。检查发现已安装版本与市场可用版本不同时，会尝试显示本机提示；系统通知设置可能阻止气泡，详细报告仍在 `~/.fiboo/marketplace/update-report.html`。电脑未登录或没有网络时，检测要等可运行时再完成。这项定时检查不会自动安装更新。

要主动查看，双击 `检查更新.cmd`；这项检查不会替换正在使用的插件。要停止额外的定时检查，按[自动更新检查说明](update-monitor.md)卸载 FIBOO 专属计划任务，不影响已安装插件。

维护脚本命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/workbuddy-market.ps1 status
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/workbuddy-market.ps1 check-updates
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/workbuddy-market.ps1 sync
```

`sync` 会同步并更新已安装插件。之后新建任务，必要时重新打开 WorkBuddy。桌面版入口可能不同于 CodeBuddy CLI，不要假定聊天中的 `/plugin`、`/reload-plugins` 是桌面端支持的命令。

## 遇到问题

| 现象 | 检查方法 |
|---|---|
| 市场拉取失败 | 检查公司网络/VPN和仓库读取权限；在同一用户身份下确认 Git 能读取仓库 |
| 没有更新 | 运行 status 查看公司市场的 autoUpdate 与最后同步时间，再运行 check-updates |
| Kimi 未连接 | 确认浏览器扩展已启用、本地桥接程序已启动、版本匹配 |
| 钉钉没有权限 | 使用自己的组织身份重新授权，并申请资料库访问权限 |
| 图片生成未配置 | 在 Wave 插件敏感配置入口填写 Key |
| 升级后当前任务仍是旧行为 | 新建任务或重启 WorkBuddy，避免把已经开始的任务当成新版本验证 |

向管理员反馈插件名、版本和错误信息即可，不发送密钥、Cookie 或登录配置文件。
