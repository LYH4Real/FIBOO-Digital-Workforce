# FIBOO 市场工作流接入

本文件连接独立插件，避免把产品资料、员工账号或历史任务写进策划插件。所有任务材料保存在员工选定的工作目录。市场更新只替换插件代码和流程。

## 1. 实时取得产品资料

用户要做 FIBOO 产品内容时，读取当前已安装的 `fiboo-product-materials` Skill，使用其 `find → get → 按需下载 PDF/主图` 流程。多规格且无法从需求判断时选择明确的记录；不要把共用 PDF 视为所有规格都相同。

DWS 使用员工自己的钉钉登录及权限。命令不在 PATH 时使用 `DWS_EXECUTABLE` 或 `--dws` 指向 `dingtalk-cli` 提供的程序；不要复制维护者的账号配置。权限失败与零命中分别说明。

接收实际生成的 `product.json`、`product-context.md`、按页提取的 `source-pages.json`（如有）和下载文件。资料获取技能没有生成 `source-pages.json` 或本地文件时，将其列为缺项，不补造。

## 2. 映射到策划的事实与素材

| 资料获取输出 | 策划接入位置 |
|---|---|
| `base_id`、`table_id`、`view_id`、`scope`、`retrieved_at` | 本次来源说明及范围/获取时间；不是审批或有效期证明 |
| `product.record_id`、`product.fields` 中产品名称/系列/规格等 | `product_scope` 与各事实的适用 SKU；同名不同记录分别处理 |
| `product.fields` 中卖点、Slogan、上架状态、更新字段 | 对应事实的来源候选值；保留原字段定位，不自动标成允许宣传或人类已确认 |
| `missing_fields`、`limitations` 与资料间冲突 | 本次缺口与冲突；不使用另一产品填空 |
| `product.json` 与 PDF 的真实绝对路径、页码/原文位置 | `01-product-facts.json.sources[]` 中 `kind: file` 的可复核文件与定位 |
| 下载工具返回的主图/包装图路径、SHA256、记录身份 | 实际查看后写入产品素材记录；不得从文件名或下载成功推断图片内容 |

按[阶段文件合同](workflow-gates.md)编制 `01-product-facts.json` 并运行事实检查。`product.json` 是来源 JSON，**不能直接重命名当成策划 facts JSON**。字段状态按真实依据填写；解决冲突所需的 `user_confirmation` 只能引用用户真实的明确确认。

营销资料、标签、PDF 相互冲突时保留各项来源；下载成功或脚本检查通过不决定哪个说法优先。具体 SKU 法定类别、广告资格、发布主体和渠道按[食品与平台表达规范](food-platform-rules.md)处理。

## 3. 获取本篇小红书参考

用户提供链接时，优先使用 `xiaohongshu-note-fetch` 当前能力，保留原链接、标题、正文、图片顺序和成功落盘文件。浏览器访问或交互需要 `kimi-webbridge` 时，先读其 Skill 并确认浏览器扩展连接；从宿主实际能力调用，不猜固定服务端口或工具名称。

只读取任务所需笔记。登录/访问受限时保留已取得范围，不能绕过权限、编造正文或把封面冒充全部内页。参考原图实际保存到同机路径后，逐张视觉读取并形成 `02-reference-manifest.json`；后续请求将对应原图真实传入 `image_paths`。

## 4. 产品包复用与实时源更新

`product_cache.py check` 只检查本地文件是否变化，**不能证明钉钉资料表或云端 PDF 没更新**。每次新任务开始时，使用同一 `record_id` 和范围重新取得当前记录，比较具体产品字段、资料链接及附件元数据；不能只因本地哈希未变就声称已同步云端。

新查询的 `retrieved_at` 本身变化不等于产品变更，勿仅凭整份 JSON 哈希变化判定业务事实变化。记录关键字段/附件/链接变化时，重新下载并读取相关材料，再建立新版本产品包，旧任务批准不沿用。资料链接指向的文件可能原地更新；本任务依赖该 PDF 时应重新下载核对文件哈希，必要时重读变化页。无法联网核验而用户明确接受离线资料时，注明缓存日期与未核验的新鲜度。

单篇任务内已经读取且未发生来源变动时可复用；不要每个段落重复拉取同一资料。产品包的生成和核验仍采用[产品预处理](product-preparation.md)，不能因新增市场插件而跳过原有事实/参考/策划确认。

## 5. 使用 Wave Image

调用 `wave-image` 的实际工具列表或 `server_info`，核对当前协议与[生图 MCP 合同](image-mcp-contract.md)一致。服务工具可能带宿主命名空间；预检报告中的逻辑工具名用于匹配真实工具，`arguments` 原样传递。

没有用户确认对应策划版本时，停在已交付的 HTML。获确认后，先运行原有预检，再调用 MCP，保存真实完整返回，检查实际文件、数量与尺寸。生成结果交付人工审稿；没有图片内容审核记录时不声称内容已通过，也不自动发布。
