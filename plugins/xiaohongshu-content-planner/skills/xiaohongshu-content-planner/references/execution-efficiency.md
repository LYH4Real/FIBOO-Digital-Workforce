# 执行效率：少做重复整理，不减少真实确认

这是执行层的效率约定，保留内容策划方法和产品露出策略；生成后默认做文件与尺寸检查并交付人工审稿，专项视觉评估仅在用户明确要求时执行。

有已就绪产品包时，从[单篇快速生产](fast-production.md)开始；尚无产品包可先[产品预处理](product-preparation.md)。本页只用于确认后的请求编译，不需要每篇先把全部方法文档重读一遍。

## 已确认的参考图任务：一次编译请求

优先使用 `scripts/prepare_generation.py`，不要每个任务重新编写路径映射、复制提示词、拼接request的小脚本。它读取当前输入、验证确认文件和报告、按参考图片ID匹配路径，一次产生 `request.json` 与 `preflight.json`。标准输出只有文件位置和页数，不重复输出完整提示词。

```text
python -X utf8 scripts/prepare_generation.py --plan <03-plan-v1.json> --facts <01-product-facts.json> --facts-report <01-product-facts-report.json> --reference-manifest <02-reference-manifest.json> --reference-report <02-reference-report.json> --approval <04-plan-approval-v1.json> --output-root <本任务独立输出目录>/runs --concurrency 2
```

路径包含空格时使用引号。脚本会在output-root下新建真实时间＋随机标识的运行目录，不覆盖旧文件。输出文件不等于已调用MCP；仍须将 `preflight.json.mcp_call.name/arguments` 原样交给工具并保存实际返回。它不伪造批准、不自动生图，也不能证明用户确认和事实记录的真实性。

- 仅支持每页均有原帖参考的 `edit_batch_images` 标准任务；无参考或特殊工具任务沿用现有明确请求合同，不临时猜测转换。
- 原帖图按 `reference_image_ids` 顺序排列在前，产品图按 `product_image_paths` 顺序在后。提示词的图序必须与此合同一致；有其他图序时先在策划中明确，编译器会拒绝不一致的显式 `image_paths`，不会自动改提示词。
- 不改变批准版的正文、prompt、size或页序。`【参考强度】` 后允许换行/空白；不必为了格式检查修改批准版提示词或重新补批准哈希。错误、混合或缺少参考强度仍报错。
- 可用 `--pages <页面ID> ...` 仅准备失败页，仍保持批准版页序；不会再次准备其他成功页。这不是自动重试调度器，仍须核对实际失败原因和用户授权预算。
- `--model`、`--response-format` 仅补充未指定值；与已批准值冲突时报错，不静默更换模型或响应方式。
- 新快线的 `input_binding` 策划更严格：生成请求必须与批准版逐页一致；模型/响应格式需在批准前写入策划，批准后不能靠命令参数新增。参数未指定则保持工具默认。独立预检也校验来源绑定，不能改完 request 再借旧批准作图。
- 编译器单批并发范围1–3，未指定默认3；这不是整台机器的全局限流。示例2仅作小批试验，不代表服务已通过容量压测。多会话同时执行时应降低各批并发，先测总吞吐与失败率，不能声称把并发调大就一定更快。
- `--retries` 默认0，避免隐式增加付费请求。只有已有授权才显式设置；默认不执行视觉自动返工。专项审图及已有返工授权下，传输重试与视觉返工预算不能分别无限累加。

## 减少返工与上下文往返

先枚举任务材料，区分输入、历史结果和当前输出；只实际解读与本次任务有关的资料，不让成图目录被当作新产品事实反复读入。两条参考笔记必须有各自独立的可写目录，不共用ref_p1或计划文件名。

产品事实与参考识别只在材料未变化、原有证据真实有效时复用。遇到冲突先问用户；旧AI生成稿、Agent自填confirmed或自写独立评分不构成可信缓存。

生成后只运行文件、格式、数量和真实尺寸检查，交付图片供用户人工审稿。默认不启动独立 Agent/视觉工具、不裁剪或放大作审查、不七项评分、不视觉自动重试。用户明确要求专项审图时按[专项评估合同](workflow-gates.md#6-可选专项独立视觉评估与有限重试)执行；允许复用独立评估器并批量检查，不要求每页重建 Agent。

本地保存全量请求、原始返回和检查结果；对话中只报告新增结果、失败页与关键原因。不要为了补结果文件而重新手写一份MCP返回。

平台错误/模型额度不足、MCP空返回、下载失败、尺寸失败、画面失败分别处理。模型额度和云端错误不是Skill可以消除的；空返回不能视为成功，也不要重复付费生图探测。尺寸不符先保留证据诊断，不对同样参数无止境重跑。

## 测速口径

分别记录策划、等待用户、MCP调用、结果整理、文件检查与实际发生的返工。默认生产计时在待审图片交付时结束，人工待审状态单列；用户所请求的专项视觉评估另记范围与耗时，不与默认交付混为同一质量口径。MCP内记录的页耗时若包含请求与下载，不得标为模型纯推理时间。嵌套时间按区间并集，不相加。离线测试通过只证明程序行为；真实节省时间必须在相同任务、相同模型、相同页数、相同审核范围和可比负载下对照测量。
