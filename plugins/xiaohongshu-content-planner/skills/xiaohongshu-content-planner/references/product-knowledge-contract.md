# 产品资料接入规范

## 使用原则

主 Skill 不内置任何具体产品的事实或素材。产品信息可以是用户上传或指定的文档、图片、表格、项目文件或当前对话中的已确认说明；不要求统一扩展名、固定目录或预建知识库。

FIBOO 公司产品默认通过市场中的 `fiboo-product-materials` 获取实时资料，具体映射和缓存新鲜度要求见 [市场工作流接入](fiboo-marketplace-workflow.md)。读取成功、表中有卖点和营销资料较新，都不等于用户已批准文案或功效表述。

仅做竞品/参考拆解无需目标产品资料。需要写目标产品内容时，从已有资料中提取本任务必需事实；只补问会改变结果的缺口，不能用竞品或相似产品代替。

## 定位与读取

1. 优先读取用户明确指定的附件、文件或目录；仅在其指定范围内查找，不搜索无关目录。
2. 识别产品、口味/规格、适用日期及资料状态。多产品且无法判断目标时再询问；对比任务按产品分别记录事实。
3. 将字段来源保留为文件＋页/位置或对话说明；不能把草稿状态自动改为批准。
4. 将已提取事实保存为本任务上下文；如需落盘，放在当前任务输出目录，不能写回已安装 Skill 作为通用规则。

## 名称与版本变化

分别记录当前对外名称、历史别名、实物包装名称及适用时间。用户明确说明已改名而包装尚未更换时，新文案用有效对外名称，真实包装图保留包装字样；不把二者简单判为冲突，也不自行更改包装。

对同一口味/规格的产品名、卖点、用量、包装、数值或功效存在真实冲突时，列出全部候选值和来源。产品名、核心卖点/固定表达、用量或包装信息任一冲突，都必须在输出策划 HTML 前 HITL：停止策划与生图，向用户提出合并后的具体问题。最新营销稿不能自动覆盖标签数据；文件日期较新也不能代替用户确认；参考案例不能覆盖本次已确认信息。

把关键事实整理为 [生产阶段门](workflow-gates.md) 中的 `01-product-facts.json` 并运行检查。只有明确的用户确认可以写入 `resolution.source: user_confirmation`；Agent 不得自行选择候选值或把冲突降级为提示。

## 按任务提取字段

以下是整理目录，不是每次提问必填表。仅使用当前任务需要且有依据的字段：

1. 产品标识和资料版本/日期（未提供版本时记录来源，不编造版本号）；
2. 对外标准名称；
3. 实物包装名称及名称差异规则；
4. 适用品牌和产品范围；
5. 已批准的核心表达；
6. 配料、营养和使用方法；
7. 每个事实的适用口味、规格和口径；
8. 目标人群与适用场景；
9. 允许表达；
10. 需要谨慎表达的内容；
11. 禁止表达；
12. 必带词、搜索词和品牌词；
13. 产品外观、标签、配件、质地或使用状态参考图（按产品类别选择）；
14. 维护人与最近确认日期；
15. 尚未解决的冲突。

食品健康类任务另外按需记录：具体 SKU 法定类别及依据、拟发布渠道和主体、注册/备案与广告批准内容（适用时）、营养声称的标签/检测依据、真实体验来源与授权。优先复用有效资料，不每篇重新要求用户填表；品牌内部“批准卖点”不能替代法定资格。缺少这些信息不自动把产品当普通食品或保健食品，先排除待核的功效主张。

## 外部图片路径

- Skill 内部的 `references/` 相对于安装目录；产品素材相对路径相对于提供该路径的产品资料文件目录，不能相对于 Skill 目录解析。
- 用户明确指定素材目录时以其为准；附件应先取得实际可访问路径。图片仅显示在对话中不等于本地 MCP 可以读取。
- 调用当前本地生图 MCP 前，把每张参考解析为同机绝对路径并验证存在。远程图片须先通过当前环境允许的方式取得为本地文件；不能把 URL 直接当成本地 image_paths。用户提供过参考图文时，原帖参考图和产品图都要分别解析，不能只解析产品图。
- 只缺产品图时可先完成文案和分镜，暂不执行依赖图片的编辑生成。

## 多产品调用规则

- 单产品任务绑定明确产品；对比内容可以读取多个产品资料，但不得混用数据、图片或使用方法。
- 不同口味、规格、批次或包装的数据不能默认通用。
- 未确认信息保留待确认标记，不写入事实性成品；业务正式发布仍采用产品负责人确认的资料。
- 历史案例只证明内容形式可参考，不证明其中产品事实仍然有效。

## 健康与营销表达

生成时应用 [食品与平台表达规范](food-platform-rules.md)，区分法律底线、具体产品资格和渠道规则；不把参考案例中的允许用语写入产品包作为永久白名单。

- 配料和营养数据按标签原文表达，不自行换算成扩大性结论。
- 类别声明、营养或健康术语必须有对应产品资料依据，不能从其他产品继承。
- 不将相关性、体验或营销概念写成疾病预防、治疗或确定功效。
- 个人体验不能伪装为已经发生的真实经历。
- 科普结论需要可查证来源，并与产品营销表达分开。
