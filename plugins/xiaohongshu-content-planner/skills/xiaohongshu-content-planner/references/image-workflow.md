# 生图 MCP 工作流

分镜和提示词读取 [参考驱动的视觉方法](visual-prompt-method.md)；准备调用或验收尺寸时读取 [MCP 参数合同与离线检查](image-mcp-contract.md)。它们分别负责“画什么、参考哪张”与“实际传什么、返回多大”，不能互相替代。

## 工具选择

- `generate_image`：任务没有任何参考图文、没有产品还原要求时的单张新画面。
- `generate_batch_images`：任务没有任何参考图文，多张独立画面且无需产品参考图。
- `edit_image`：用户提供过参考图文，或需要还原产品/构图时的单张图片。
- `edit_batch_images`：用户提供过参考图文的多页内容；每页有独立原帖参考图、必要产品图和提示词。

用户提供过参考链接、图文或图片时，禁止退回生成工具；每个页面都用编辑工具，并至少传一张对应的原帖参考图。涉及真实产品时同时传目标产品图，不能仅靠文字描述重新创造包装。

## 生图前检查

完整生产任务必须先完成任务目录清单、产品事实门、参考图语义清单、策划 JSON/HTML 和用户确认，具体见 [生产阶段门](workflow-gates.md)。没有策划确认文件或策划文件哈希已变化时，不得调用 MCP。

每页先明确页面目的、页面文字、结构参考图、产品参考图、特殊物件参考图、场景和人物要求、禁止项、与前后页的连续关系，以及已约定保留或改变的元素。将 [参考拆解](reference-analysis.md) 中的迁移映射落实到每页。缺少关键产品图时仅暂停依赖它的图片生成，仍可做文案、分镜和不依赖该图的分析。

用户在对话中修改标题、正文、页面文字、参考程度或尺寸时，以最新表达为准，更新对应分镜和请求；不要求用户另填网页或重复已经确认的决定。

产品图片路径由任务提供，解析方法见 [产品资料接入规范](product-knowledge-contract.md)。先实际查看原帖参考图和产品图，再将可访问的同机绝对路径交给编辑工具。链接图片未能保存为本地文件时，暂停生图并补素材；不能只传产品图。

## 参考图角色

- 结构参考：只决定版式、机位、元素数量和阅读顺序。
- 产品正面：决定包装比例、颜色、文字和品牌方向。
- 产品背标：决定配料表、营养表或使用说明。
- 配件和质地：决定当前产品所需物件的形状、颜色、大小和状态；没有配件的产品不要求额外提供。
- 使用状态：决定本次产品在实际使用中的外观，如饮品状态或材质变化，只在相关页面使用。
- 场景参考：决定桌面、环境、人物和光线。

在提示词中逐张说明角色，不允许模型从结构参考图继承竞品产品。

每页在提示词中写明 `【参考强度】严格参考`、`【参考强度】中度参考` 或 `【参考强度】轻度参考`。强度来自四维参考合同在该页视觉维度上的综合结果；严格参考逐项列出要还原的空间和拍摄特征，轻度参考则明确不复制布局及人物。

仅借鉴配色时，结构图只约束色彩，不同时继承图文布局、人物或产品摆放；仅借鉴构图时同理。整篇迁移时维持已确认的逐页功能，再明确哪些元素需依据目标产品重新设计。

## 提示词结构

按 [视觉方法](visual-prompt-method.md) 写逐页自包含提示词：整组风格锚点、每张参考图角色、区域布局、机位、光线、物件状态、准确文字和禁止项。真实摄影、插画或拼贴等风格服从已确认意图，不把“素人感”设成所有任务的固定风格。

本项目无其他要求时采用 3:4 竖版 `1248x1664`，这是项目默认值，不是平台强制尺寸或所有图像服务的通用约束。它符合当前 Waveeee MCP 0.3.0 客户端尺寸校验；实际服务是否按此返回仍需运行后核对。用户选择其他尺寸时以其要求和当前服务合同为准，不悄悄退回方图。

每个单图 `arguments.size` 或批量 `arguments.tasks[i].size` 均须显式填写。运行 `image_request_guard.py preflight` 后只将输出 `mcp_call.arguments` 传给对应 MCP 工具；不要将整份记录包作为工具参数。具体四种调用示例与可选参数见 [调用合同](image-mcp-contract.md)。

## 批量任务

- 每页使用稳定、唯一的任务 ID。
- 每页单独提供提示词和参考图，不能让所有页面共用模糊的参考图集合。存在参考任务时，每条 `image_paths` 至少包含该页对应或最接近的原帖图片；再按需增加产品、质地、配件或连续性图片。
- 每次调用使用未用过的运行 ID 与独立目录；批量工具会写固定名称 manifest，重试不得复用旧运行目录。生成前保存请求，返回后保存原始结果；单图工具没有 manifest，也要自行留存这两份记录。
- 单页失败不能覆盖其他成功页面。
- 失败重试仍然使用同一业务约束，不能为了出图删除产品和合规限制。批量参数建议首轮 `n:1`、`retries:0`，避免额外请求不易追踪；如用户已授权重试预算则沿用其上限。发现返回尺寸不符时保留证据并停止相同参数的重复付费调用，说明问题后再决定是否重试。

## 生图后检查与交付（默认）

运行 `image_request_guard.py inspect`，核对文件存在、真实格式、图片数量、实际存储宽高和比例，而不是相信请求或 manifest 中的 size。它不完整解码图片，也不检查画面与文字。比例相同但像素不符也要如实报告，不自动裁切或放大来冒充原始生成通过。

默认检查到此为止，交付图片、实际尺寸和检查报告，由用户人工审稿。标记“文件与尺寸检查通过，图像内容待人工审核”；检查失败时逐页报告失败或缺失，仍可交付已生成的图片供查看，但不能标成检查通过。人工审核待完成不阻塞图片交付，也不代表图像内容、文字、产品准确性、合规或发布验收通过。

默认不启动独立 Agent 或视觉工具，不逐页自动目检、不制作裁剪或放大图作审查、不做七项评分，也不进行视觉自动重试。`visual_review_required:true` 表示内容仍待审核，不是自动调用指令。保留真实请求、逐页参数、原始返回、检查记录与生成图片；当前 MCP 的单图工具返回路径，批量工具另有 manifest，不宣称不存在的日志或图片已产生。

## 用户明确要求时：专项视觉评估

仅在用户明确要求专项审图时读取并执行[独立视觉评估合同](workflow-gates.md#6-可选专项独立视觉评估与有限重试)，保留独立原始记录并运行 `visual_review_guard.py`。可由同一独立评估器批量处理多页，不要求每页或每轮重新启动 Agent；每页仍须对应原图、成图、约束和结果。整图优先，只有专项问题需要时才局部放大或裁剪辅助检查，保留原始成图，不将辅助图冒充交付原图。

专项范围内检查产品是否畸变或镜像，品牌、名称、数值和单位是否准确，所需配件与质地是否来自正确参考，页面文字是否完整，是否出现额外功效、认证或水印，以及多页连续性、参考维度与事实风险。不能用小缩略拼图判断包装细字。

严格参考页逐项对照原图：页内元素数量、相对位置、主体占比、机位、裁切、文字层级、光线和生活细节；中度/轻度页只检查合同选中的维度，不能因为没有复制未选维度而判失败。

专项评估未通过时只报告实际可观察差异，按用户已有返工授权处理失败页；审图请求本身不授权新增付费生成。启用视觉返工时默认最多2次、最高配置3次，每次保留新请求、原始返回和评估证据。没有独立能力则标记“专项视觉未测”，交付图片并转人工，不伪造分数或验收结论。尺寸、视觉、文字、产品事实及业务审核分别记录，未做的项目写“未测”，不统称“可发布”。
