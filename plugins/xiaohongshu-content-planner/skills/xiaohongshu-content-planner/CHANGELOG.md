# 变更记录

## 0.3.2 2026-09-16（FIBOO 市场分发适配）

- 接入 FIBOO 实时产品资料技能及小红书笔记获取、Kimi 浏览器、钉钉 CLI、Wave Image 的市场依赖；工具调用使用宿主实际暴露的名称。
- 新增资料交接约定，保留实时来源身份和权限边界；替换示例盘符与旧任务表述。
- Python 生产脚本沿用 0.3.1，保留策划确认、原图入请求和人工审稿行为。

## 0.3.1 2026-09-16（人工审稿与食品表达规范测试版）

- 按用户选择，生图后默认仅做文件/格式/数量/实际尺寸检查，交付图片并标注人工待审；不自动开启独立 Agent、视觉评分、裁剪放大或视觉返工。专项视觉评估保留为明确请求后的可选路径。
- 新增食品与平台表达规范：区分普通食品、具体注册/备案保健食品等身份和自然笔记、蒲公英、聚光渠道；把资质、证据与整体暗示检查前置到策划，不新增每篇独立合规 Agent。
- 根据用户两份规则文档记录渠道差异与内部冲突，结合官方规则校核；不生成规避词表，不把“使用后状态变好”当通用合规句式，不虚构亲历或将真实体验自动变为保健功效许可。
- 保留产品事实 HITL、生成前参考图识别、策划 HTML 确认、真实原帖入请求和请求日志。默认交付不等于视觉验收或发布许可；计时器对人工待审仍记录 partial。
- 本版不变更生图 MCP 配置，不包含原规则 DOCX、案例截图或公司产品资料；不保证平台过审或十分钟端到端完成。

## 0.3.0 2026-09-08（双入口提速测试版）

- 增加产品预处理入口：离线打包有来源的事实、产品图语义与明确扫描范围；保留完整来源和输入文件哈希，检测范围内新增、删除、同路径内容变化。资料包在业务目录维护，不进入 Skill 或 GitHub。
- 增加单篇快速生产入口：复用未变化的产品解读，实际读取新 brief 与参考图；一次生成事实/参考报告、策划 JSON 和只读 HTML，不创建批准、不调用生图。当前快线面向每页有参考的批量编辑任务，其他情况保留冷启动流程。
- 策划绑定本次输入，产品包或 brief 改变后旧批准失效；独立请求预检核对批准的页序、提示词、尺寸、数量、模型及原帖/产品图片顺序，防止整理请求时偏离批准内容。
- 新增阶段计时器：区分 prep/cold/warm、等用户、生图、验图、返工和平台阻塞；失败样本保留。时间阈值与质量验收分开，不把调用者声明当作真实质量证据。
- 精简入口，按需加载方法文档；产品露出按本篇需要，不恢复历史最低页数限制，不改本轮以外的内容策划方法论。
- HTML 前提前核对生成参数；必需的非关键产品事实冲突也会阻断。新脚本使用 Python 3.10+ 标准库，无网络和付费调用。
- 不升级或替换 MCP；继续兼容已有 0.3.0 观测补丁。仍未集成可信独立视觉评估服务，不解决 TRAE 云端超时/额度问题，不承诺实际十分钟达标；需要相同页数的真实对照测试。

## 0.2.1 2026-09-08（提速测试版）

- 新增固定请求编译器 `prepare_generation.py`：从已确认策划与参考清单一次生成请求和预检，保留提示词、尺寸、页序、图序与生成数量，减少临时脚本和反复整理。
- 支持仅准备指定失败页；使用真实时间与随机运行标识隔离输出。默认传输重试为0，不隐式增加付费请求；并发上限3是单批限制，不是全局限流。
- 参考强度标记允许换行与空白，不再为了排版修改已批准策划；错误强度、混合值仍被拒绝。
- 纳入已核验的材料目录扫描修正：CLI成功时正确返回，支持明确include/exclude范围；选中材料仍逐次计算哈希，不自动跳过变化。
- 安装包明确包含请求编译器及效率说明。78项离线回归测试通过；配套MCP观测补丁另包分发，不含密钥。
- 配套MCP增加逐页即时日志、UTC起止时间、单调计时和解析后的请求模型；MCP协议版本仍为0.3.0，不冒称与Skill版本相同。
- 本版不调整内容策划方法论，不承诺消除TRAE云端4054错误或模型额度限制；实际提速仍需对照测试。事实/视觉JSON检查不证明真实独立评估发生，也不能保证产品资料源文件完整版本绑定。

## 0.2.0 2026-09-08

- 完整生产流程调整为“递归读取任务目录 → 产品事实冲突 HITL → 参考图逐张语义清单 → 策划 JSON/轻量只读 HTML → 用户确认 → 生图 → 独立视觉评估 → 有限自动重试”。
- 新增 `workflow_guard.py`：生成材料清单，阻断产品名、核心卖点/固定表达、用量和包装信息冲突，校验参考图语义清单、策划文件与用户确认哈希。
- 新增 `build_plan_html.py`：从已验证策划 JSON 生成只读 HTML；不恢复 v0.1.3 的重型交互审稿工作台，修改仍通过 Agent 对话完成。
- 生图请求升级为 schema v2；旧请求无法绕过策划确认门。有参考时语义清单 ID 与真实路径必须一一对应，防止文件名/页序错配。
- 生图预检报告增加 `page_request_records`，从实际 MCP 调用逐页保留任务参数和公共参数；继续保留完整请求、原始 MCP 返回与真实像素检查。
- 新增素人感方法：手机机位、场景混光/轻直闪、非对称构图、有限生活痕迹和商业广告感禁用项；产品不再默认每页露出。
- 新增 `visual_review_guard.py`：只接受独立视觉模型、视觉评估工具或人工复核的原始记录；严格参考、产品/文字/事实和素人感使用固定阈值，失败页默认最多自动重试 2 次，到上限转用户或人工。
- 自动测试增至 59 项；真实 TRAE 视觉评估工具接入、付费 MCP 自动重试和八业务案例仍需端到端验证。

## 0.1.5 2026-09-07

- 移除交互审稿工作台、HTML 模板、决策 JSON 协议和相关运行脚本；默认直接输出可在对话中修改的内容策划方案，末尾只保留 0—3 个关键问题。
- 将参考范围升级为四维参考合同：叙事逻辑、逐页构图、图片风格、文案语气分别明确严格、借鉴或不沿用；模糊参考先给建议合同再问一个具体问题。
- 增加“严格视觉替换”模式：高度还原参考页数、逐页功能、元素数量与位置、主体占比、机位、裁切、文字层级、光线和生活质感，同时替换为目标产品、确认事实与新文案。
- 用户提供过参考图文时，每个待生成页强制使用编辑工具并传入至少一张原帖参考图；轻度参考也不能只传目标产品图。
- 生图请求包新增 `reference_context`；离线预检检查逐页原帖路径、实际 `image_paths`、编辑工具和严格/中度/轻度提示词标记。
- 保留 v0.1.3/v0.1.4 标签、安装包和外部已生成 HTML 供历史回看；当前安装包不再包含工作台组件。
- 本版仍需在 TRAE + DeepSeek/GLM 和既定八案例中验证模型对四维参考合同与强制原图规则的实际执行效果。
