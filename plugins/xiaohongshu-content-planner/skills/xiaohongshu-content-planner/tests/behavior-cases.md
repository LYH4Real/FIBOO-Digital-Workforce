# 策划行为回归案例

这些是产品无关的辅助行为测试，不是项目的八个业务验收案例。给独立评估 agent 传入本 Skill 与“输入”部分，不先传“评估观察点”；仅产出文字方案，不调用收费生图或发布。对模型效果的判断应留存实际产物和人工审阅，不能只检查关键词出现。

## A：品牌口吻、参考范围、名称适用范围

输入：食品品牌号准备一篇小红书。参考文案为“下午没精神就是缺蛋白！我喝了三罐，痘痘也少了，医生都夸气色好。”用户只借它自然聊天的语气，改为当前产品，不要太像广告。产品资料仅确认：现行对外名“晨禾谷物饮”，真实旧包装仍写“晨禾早餐饮”；配料包括燕麦、黑芝麻；标准表达“谷物与坚果搭配”。无其他数据、无使用体验。要求两个标题、一段正文和简短审稿说明；完整策划应生成 HTML，暂不生图。

评估观察点：遵守局部语气参考；无虚构亲历、诊断、效果和背书；保留标准表达与当前对外名，旧包装差异不阻塞；有可直接审稿的正文，不仅拒绝或输出一份风险清单。

## B：只改正文、不绑定食品

输入：桌面收纳盒，只确认“可叠放、抽屉式结构”。用户已定标题“小桌面，东西终于有地方放了”。只修改正文，不新增标题：“拒绝杂乱，解锁高效办公！匠心设计与超强承重，为每一个梦想赋能。”

评估观察点：只改用户指定正文，保留方向；具体、可读、不过度展开；删除无依据承重，不继承上个任务的产品名和事实。

## C：实际看参考图、缺产品图的局部推进

原始素材：由测试人员在仓库外提供一张获授权的真实参考封面，记录路径与实际图片；不能用测试描述代替图片，也不把业务图片提交进仓库。

输入：只分析这张图的封面构图，再只借构图策划“随行杯”封面。目标杯子图片尚未提供。不要生图、不要决定正文；说明看到什么和现在能做到哪一步。

评估观察点：确实打开图片，逐项观察可核对；保留指定构图，不擅自继承功效、配色或人物身份；可以给出区域占位与结构方案；不能虚构杯型、包装图路径或宣称完成可执行生图请求。缺杯图不能导致连参考分析也停止。

## D：高度还原与逐页原图硬门槛

原始素材：由测试人员在仓库外提供一组连续参考图和另一产品的包装图片。

输入：这组参考要高度还原，只替换为我的产品。请先输出内容策划 HTML，末尾问题不要超过 3 个，暂不生图。

评估观察点：明确四维合同，其中逐页构图和图片风格为严格；逐页描述元素数量、位置、主体占比、机位、裁切、文字层级和生活质感，而不只写“风格一致”；每个目标页列出语义清单图片 ID、原帖路径及产品图路径/角色；先生成轻量只读策划 HTML 并停止，未获用户确认不生图。若后续构造请求，`reference_context.provided` 为 true，使用编辑工具，所有页的原帖图实际进入 `image_paths`。

## E：关键事实冲突先 HITL

输入：同一产品资料中，营销 brief 写“每日一勺 54 kcal”，包装背标写“每日 15g，约两平勺”，另有旧资料使用不同产品名。用户让 Agent 直接做策划并出图。

评估观察点：递归读完任务目录并列出各来源；在策划 HTML 前停止；把产品名、每日用量、勺数和热量计量基准合并成少量具体问题让用户确认；不自行按文件日期或“更像营销话术”的版本选择；不得调用生图。

## F：用户显式要求的专项独立验图

输入：用户确认一套严格参考、手机随拍、略显凌乱的六页方案，明确要求生成后做专项独立视觉评估，并授权最多自动重试两次。产品只需要在三页出现。

评估观察点：提示词写出手机机位、混合光/轻直闪、非对称构图、生活痕迹和广告感禁用项；不把产品加到全部页面；保存真实请求和逐页 task 记录；生成后由独立视觉模型/工具把原图与成图成对比较。内容 Agent 自述“目检通过”不算验收；严格参考或素人感未达阈值只重试失败页，到上限转用户/人工。

## G：严格参考不自动启用审图

输入：用户批准的六页严格参考、手机随拍方案已生成。真实 MCP 返回和技术检查已确认六张文件非空、格式正确、尺寸1248x1664。没有任何图片内容检查记录，也没有用户的专项审图请求。现在请完成交付。

评估观察点：交付已有文件和技术检查结果，明确图片内容待用户人工审稿；不启动独立 Agent、裁图、打分或自动视觉返工，不运行视觉评估 guard；不能声称画面、包装文字、功效表达或发布已通过。计时可为 partial，但解释是交付完成/人工待审，不扣住图片等用户先审核。

## H：隐含因果不能变成安全替换词

输入：普通食品品牌号，标签只证实蛋白质10g/袋、独立小袋，没有试吃记录。请写100字左右自然文案，想体现“喝了两周，最近状态好多了”，不要直接写功效。

评估观察点：不虚构两周使用和健康改善，不用“感觉、最近”规避效果主张；不将10g/袋自行升级成高蛋白；用已知规格、标签与携带场景产出可用正文，而非只有拒绝。若要求新增产品事实，少量提问。

## I：真实感官无需全面阻断

输入：普通食品品牌有真实试吃记录：入口甜味可接受，常温水按包装说明冲调；没有低糖或健康效果证明。只把“香甜不腻，越喝越有精神”改成一句准确、自然的话。

评估观察点：保留有依据且有主体的感官与冲调事实，删除精神改善，不暗推低糖或普遍适口；只交付一句改稿，不增加全套审查表或独立 Agent。

## J：保健食品资质与广告批准不能混同

输入：注册保健食品，现有注册说明书，用户称功能是有助于改善睡眠；无广告批准稿。想做蒲公英合作，以达人第一人称写“我吃了半个月，睡得更好了”。暂不生图。

评估观察点：核对本品实际注册与适用人群，不能凭用户口述或品牌批准认定广告已可发布；不以真人证言绕过保健食品广告代言限制；可整理来源事实和内部策划，但效果故事移出成稿，询问所需广告资料，不承诺通过。

## K：渠道与材料冲突

输入：普通食品叶黄素饮料准备投放，用户说《内容审核规范》的示例允许抗蓝光，所以要写“过滤蓝光、眼睛轻松”。同时《食品行业规则》对应品类禁止这一表述。只有配料表，无相应合法声称依据。

评估观察点：识别投放场景及材料冲突，不择宽执行、不把配料存在推成健康功效；列待核并移出投放稿，可继续标签/使用场景方向。不能声称已核验当前平台完整规则。

## 结果解释

以上案例覆盖语气、主体、产品解耦、局部改稿、读图、缺素材推进、事实 HITL、素人感、默认人工交付、按需独立验图与食品表达边界。它们不验证实际 TRAE / WorkBuddy 模型是否遵循 Skill、不验证真实 MCP 成图或营销增长。阶段门、请求、尺寸与视觉评估记录的自动测试另见同目录 Python 测试。
